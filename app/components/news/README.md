# Статьи без бэкенда

- `content/` — отдельный TypeScript-файл для каждой статьи; структура описана в `types.ts`.
- `model.ts` — реестр статей и поиск по стабильному ID. Порядок записей определяет порядок в архиве.
- `app/(site)/articles/page.tsx` — архив всех опубликованных статей, автоматически построенный из реестра. `ArticlesList` сначала показывает четыре карточки и раскрывает следующие порциями по четыре через кнопку «Загрузить ещё». Анимация длится минимум две секунды; после последней порции кнопка исчезает. Данные карточек передаются с сервера сразу, дополнительного сетевого запроса при раскрытии нет.
- `NewsArticle.tsx` — серверный компонент страницы: текст, оглавление, код, источники, следующая статья.
- `app/(site)/articles/[id]/page.tsx` — App Router: await params, generateStaticParams, generateMetadata, notFound.

## Добавить статью

1. Создать файл в `content/`, экспортировать объект `NewsArticle` с уникальным строковым `id`.
2. Добавить объект в `newsArticles` в `model.ts`.
3. Если статья должна попасть в подборку на главной, в соответствующей заметке `app/components/home/model/site-content.ts` задать тот же `id` в обеих языковых версиях. Карточка получит ссылку `/articles/{id}` и статус статьи. Для будущих тем `id` не указывать. На главной отображаются первые четыре записи `notes`; остальные статьи доступны в архиве `/articles`.
4. Собрать и развернуть сайт обычным способом. Контент обновляется с новым деплоем; база данных, API и CMS не требуются.

ID опубликованной статьи менять не следует: это её постоянный URL. Неизвестные ID возвращают 404. `dynamicParams = false` разрешает только маршруты из реестра.

Статьи сейчас русскоязычные: у article установлен lang="ru", в английской карточке ссылка явно подписана Read in Russian. Текст серверный и не зависит от переключателя интерфейса. Примеры кода иллюстративные, не заявлены как код клиентских проектов.

Никакого HTML из строк: контент рендерится обычными React-элементами. Для примеров кода дополнительные библиотеки не подключаются.

## Новости web.dev

На `/articles` клиентский блок `WebdevNews` получает новости через RTK Query и `/api/webdev-news`. Route Handler вызывает серверный `getWebdevNews()`, поэтому браузер не обращается к web.dev напрямую. RTK Query хранит клиентский кеш, дедуплицирует запросы и повторяет их после восстановления сети или фокуса окна. Кнопка «Обновить» запускает ручной refetch.

`WebdevNewsList` отображает по шесть новостей на странице, с номерами страниц, многоточиями и стрелками. Количество страниц рассчитывается по доступным записям RSS; архив старых выпусков не хранится. Загрузка и разбор RSS находятся в `webdev-feed.ts`; XML разбирается через `rss-parser`. Заголовки и описания выводятся как текст, ссылки допускаются только на HTTPS-страницы web.dev.

Лента и страница кешируются на час. После истечения срока следующий запрос запускает обновление — отдельный cron не нужен. При ошибке или пустой ленте показывается ссылка на блог, авторские статьи остаются доступны. Нужен серверный Next.js-хостинг с поддержкой revalidation, например Vercel. Тексты источника остаются на английском языке.

Обложки загружаются из метаданных `og:image` (или `twitter:image`) страниц публикаций. `webdev-cover.ts` разбирает HTML через `htmlparser2`, кеширует ответ страницы на сутки и ограничивает ожидание пятью секундами. Адреса картинок разрешены только с web.dev и storage.googleapis.com/web-dev-assets/. Запросы метаданных идут группами по четыре. `NewsCover` использует оптимизацию и ленивую загрузку Next Image; при отсутствии обложки или ошибке изображения показывает заглушку.
